Valid repo paths beginning with .. are falsely rejected as traversal
ToRelativePath treats any relative path starting with .. as outside the repo:
paths.go (line 168)
But the repo already has the correct check in IsSubpath: reject only .. or ../..., not names like ..generated: paths.go (line 148).
Same false-positive pattern appears in checkpoint metadata walkers:
temporary.go (line 975), temporary.go (line 1036), committed.go (line 1850)
Impact: legitimate files such as /repo/..generated/schema.json are silently filtered out of checkpoint file tracking, and checkpoint metadata writes can fail with false “path traversal detected” errors for legal child paths.
Repro shape: paths.ToRelativePath("/repo/..generated/schema.json", "/repo") currently returns ""; expected "..generated/schema.json".
Likely fix: replace strings.HasPrefix(rel, "..") with rel == ".." || strings.HasPrefix(rel, ".."+string(filepath.Separator)), and add regression tests for ..generated/file.
