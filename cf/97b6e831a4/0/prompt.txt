**Current State**
The v1.1 explain branch introduces `checkpoint.NewCommittedReadStore(ctx, repo)`, which selects the committed read ref based on settings. That is the primitive `resume` should use for normal committed-checkpoint reads.

`resume` currently still uses v1-only paths in several places:
- Main store construction: `cmd/entire/cli/resume.go:192`
- Metadata summary/session reads: `cmd/entire/cli/resume.go:277`
- Direct metadata branch tree fallback: `cmd/entire/cli/resume.go:313`
- Remote/fetch fallback paths using `GetMetadataBranchTree` / `GetRemoteMetadataBranchTree`: `cmd/entire/cli/resume.go:418`
- Single-session transcript fallback: `cmd/entire/cli/resume.go:937`

`resumeSession` delegates transcript restoration through `strat.RestoreLogsOnly`, which is implemented in `cmd/entire/cli/strategy/manual_commit_rewind.go:616`. That path also still uses the default v1 store and will need to be updated or injected.

**Recommended Scope**
Keep this PR focused on `session resume` plus the minimum shared strategy read hook needed by resume. Do not migrate all rewind behavior in the same PR unless the diff stays small. With tests, resume alone is likely close to the sweet spot for the 1kloc limit.

- `entire session resume`
- hidden alias `entire resume`, automatically covered
- resume's multi-checkpoint squash handling
- resume's metadata fallback paths
- resume's transcript restoration path

Avoid:
- `checkpoint rewind` list/interactive behavior, except where shared code must change for resume
- `review`, `status`, `dispatch`, `clean`
- remote push/fetch semantics beyond what resume already does for v1

**Implementation Plan**
1. Use `checkpoint.NewCommittedReadStore(ctx, repo)` in `resumeFromCurrentBranch`.
   Replace the direct `checkpoint.NewGitStore(repo)` read store. Keep `SetBlobFetcher(FetchBlobsByHash)`.

2. Split read-store vs write-store thinking clearly.
   `resume` is read-only for committed checkpoint storage, so it should use the committed read store. It should not write to the v1.1 ref.

3. Replace `readCheckpointInfoFromMetadataBranch`.
   The current fallback reads `strategy.GetMetadataBranchTree(repo)`, which is v1-only. Prefer reading metadata through the committed read store first. 4. Review `getMetadataTree` and `checkRemoteMetadata`.
   These fetch v1 metadata and then read v1 local/remote trees. In v1.1 mode, fetching v1 is still reasonable because v1 is the durable source, but after fetch the read should go through `NewCommittedReadStore`, letting it sync/seed the v1.1 custom ref from v1.

5. Update `resumeSingleSession`.
   The fallback currently constructs `checkpoint.NewGitStore(repo)` before `ReadRawSessionLogForCheckpoint`. Use `NewCommittedReadStore(ctx, repo)`.

6. Handle `RestoreLogsOnly`.
   `resumeSession` calls `strat.RestoreLogsOnly`, which currently creates its own v1 store. Best narrow fix: update `ManualCommitStrategy.RestoreLogsOnly` to use `checkpoint.NewCommittedReadStore(ctx, repo)` for committed reads.
