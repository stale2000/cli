# Code Review — `entire-labs-investigate` branch

## Overview

Adds `entire investigate` (labs, hidden) — a multi-agent investigation loop that lets configured agents take turns appending findings to a shared markdown doc until quorum. Includes a Bubble Tea TUI, `fix`/`show`/`clean` subcommands, GitHub issue/PR seeding via `gh`, settings/manifest persistence, and the lifecycle hook plumbing to tag the spawned agent sessions. Extracts shared helpers (`provenance`, `agentlaunch`, `gitexec`, `tuiutil`, `uiform`) so `review` and `investigate` no longer duplicate code.

**Scale:** 87 files, ~13.1k insertions / 327 deletions; 13 of the new files are package-scoped tests.

## Strengths

- **Untrusted-input handling is thoughtful**: `issuelink.go:289-300` wraps `gh`-fetched issue body + comments in a labeled `<untrusted>` envelope and defangs nested close-tags. `cmd.go:384-408` adds an interactive y/N gate before running `--issue-link` against agents that spawn with permission bypass.
- **Credential redaction**: `runGhExec` (`issuelink.go:77-94`) redacts URL userinfo from error strings via `url.Redacted()`, so an OAuth token in `--issue-link` never reaches stderr.
- **Provenance contract is clean**: `provenance/env.go` is a leaf package owning the env-var names; `agentlaunch.LaunchFixAgent` strips both families before spawning a fix session.
- **Failure modes are explicit**: manifest write is "best-effort, the docs are the deliverable"; cleanup ordering preserves recoverability ("manifest write fail leaves the run dir intact").

## Issues worth fixing before merge

### Correctness

- **`cmd/entire/cli/investigate/clean.go:138-157`** — deletes manifest *first*, run dir second. If the run dir removal fails, you orphan a `state.json` with no manifest record. Reverse the order so a failure is recoverable from the manifest.
- **`cmd/entire/cli/investigate/show.go:135`, `fix.go:128`** — read `manifest.FindingsDoc` as an absolute path with no relocation handling, while `manifest.go:51-53` documents that the field "may be a repo-relative path." Either resolve via `paths.WorktreeRoot(ctx)` on read, or commit to always-absolute and update the docstring.
- **`cmd/entire/cli/investigate/loop.go:206-209`** — `States.Save` failure between turns is logged at `Debug` and ignored. On a crash, on-disk state is one turn stale. Should be `Warn` (and arguably retry once). Same swallow at `state.go:199-201` for corrupt `state.json` in `List()`.
- **`cmd/entire/cli/investigate/tui_sink.go`** — no parent-context watcher pumps `tea.Quit` into the program. If the loop driver returns early (or cobra cancels via SIGINT), `RunFinished` is never called, the `done` channel never closes, and `Wait()` blocks indefinitely. Add a `<-ctx.Done() → program.Quit()` goroutine.
- **`cmd/entire/cli/investigate/tui_model.go:159`** — `runFinishedMsg` stomps every non-failed row to `rowStatusDone`, including queued-but-skipped agents. Preserve `rowStatusQueued` when `turnsTaken == 0`.
- **`cmd/entire/cli/investigate/tui_detail.go:57`** — footer advertises "Ctrl+C cancel" but `tui_model.go:297-301` ignores Ctrl+C in detail mode. Either route Ctrl+C in detail mode or fix the footer text.
- **`cmd/entire/cli/investigate/manifest.go:130-134`** — manifest file mode is `0o644` while `state.go:146` uses `0o600`. Manifests contain user prompts + findings content; tighten to `0o600` for parity.

### Security

- **`cmd/entire/cli/investigate/fix.go:143-162`** — `composeFixPrompt` embeds the verbatim findings body and `manifest.Topic` into the agent prompt with no envelope/delimiter. Findings come from prior agent runs that may have ingested untrusted seed content — wrap in `<untrusted source="prior-findings">` like `issuelink.go:294-300` does for issue bodies.
- **`cmd/entire/cli/lifecycle.go` adoption gate** — uses "env-present + agent-match + SHA-match". A parent shell that knows HEAD's SHA and the agent name can forge a session tag. Production code never `export`s these, so this requires user error, and the SHA gate is broken by the next commit. Worth a doc note; if you want to harden, gate adoption on a per-run secret token written to a tmp file readable only by the spawned process.
- **`cmd/entire/cli/review/env.go:73-89`** — `AppendReviewEnv` strips only `ENTIRE_REVIEW_*`, not `ENTIRE_INVESTIGATE_*`. `AppendInvestigateEnv` is symmetric (strips both). Fix for defense in depth.

### Layering / cycle risk

- **`cmd/entire/cli/lifecycle.go:24`** — imports `investigate` only for `EnvSession`/`EnvAgent`/`EnvRunID`/`EnvStartingSHA`/`IsValidRunID`. Move those into `provenance` so the binary doesn't link the whole investigate package when the user never invokes `entire investigate`. (Or use a fxlite indirection from the bridge file.)

### Test gaps

- No test mirrors `TestAdoptReviewEnv_TagsSession` for the investigate side — `adoptInvestigateEnv` is only called directly, never through `handleLifecycleTurnStart`.
- No end-to-end test asserts `Kind.IsInvestigate → CommittedMetadata.HasInvestigation → CheckpointSummary.HasInvestigation` flows through condensation.
- No coverage for `clean.go` / `show.go` / `fix.go` / `manifest.go` / `progress.go` at the package level beyond the bootstrap/loop pair.
- `agentlaunch/launch_test.go:47-49` doesn't exercise the `cmd.Env == nil → fall back to os.Environ()` branch; this fallback silently re-adds host stale provenance env if a future launcher returns an empty env.
- No test for `tui_sink.go` early-return-without-RunFinished blocking `Wait()`.

### Minor

- `loop.go:500-517` `fileFingerprint` uses size+mtime-nanos to detect findings doc changes. On FAT/older FS where mtime granularity is 1s, a sub-second edit of the same length will report `PlanChanged=false`. Modern FS are fine but worth a SHA fallback when size matches.
- `loop.go:493` failure note says `"spawn error: <exit status N>"` even when the process spawned and exited cleanly with non-zero. Differentiate spawn vs exit.
- `loop.go:519-541` defines `slogString`/`sErr` wrappers but the same file also calls `slog.String` directly via `slog` import — pick one style.

## Verdict

The new feature is well-scoped, well-commented, defends against the obvious prompt-injection vectors, and the extractions (`provenance`, `agentlaunch`, `gitexec`, `tuiutil`, `uiform`) cleanly de-duplicate review code. The issues above are mostly small correctness fixes and test gaps; only the **clean.go delete ordering**, **tui_sink unbounded Wait()**, **show/fix path resolution**, and **fix.go untrusted-content envelope** rise to "should fix before merge."
