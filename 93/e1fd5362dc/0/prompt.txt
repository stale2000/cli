# Upgrade `migrate-v2-checkpoints` to discover v2 orphans

## Goal

Add a second discovery pass to `cmd/migrate-v2-checkpoints` so it finds
v2 checkpoints that have **no `Entire-Checkpoint:` commit trailer
anywhere in history**. The current tool is trailer-driven and silently
skips these; in a v2-rollback context that is silent data loss.

## Repo / paths

- CLI source: `~/entire/cli` (work on the `tmp-migrate-v2-script-go`
  branch; there is an existing worktree at
  `~/entire/cli/.worktrees/review` that built the current binary as
  `~/entire/cli/.worktrees/review/migrate-v2-checkpoints`).
- Tool source: `cmd/migrate-v2-checkpoints/`
  - `main.go` — flag parsing + run loop
  - `history.go` — `discoverCheckpointHistory` (trailer walk)
  - `migration.go` — per-checkpoint migrate loop, report
  - `main_test.go`, `v2_fixture_test.go` — existing tests
- v1/v2 storage code (read-only context for the change):
  - `cmd/entire/cli/checkpoint/v2_read.go` — v2 reads
  - `cmd/entire/cli/checkpoint/committed.go` — v1 writes
  - `cmd/entire/cli/paths/paths.go` — file/ref constants
  - `cmd/entire/cli/checkpoint/id/id.go` — `CheckpointID`, `Path()`
- Validation runbook (already written, references this tool):
  `~/entire/cli/.worktrees/review/cmd/migrate-v2-checkpoints/VALIDATION.md`

## Why this matters

Validating the tool on `~/entire/marvin` surfaced 3 orphan checkpoints
present on `refs/entire/checkpoints/v2/main` and
`refs/entire/checkpoints/v2/full/current` but with **no commit trailer
anywhere** (checked with `git log --all --grep "Entire-Checkpoint: <id>"`,
zero hits):

- `084309642a2a`
- `6490c87f6028`
- `af602c72598d`

Each has 1 session of valid metadata and a reachable raw transcript.
Likely sources: interrupted sessions whose commit never landed,
amended-away commits, dropped branches. This pattern will exist in
every repo doing the rollback. The current tool's report counts these
as "not discovered at all" — they do not show up in the
`missing v2 checkpoint metadata` or `missing raw transcripts`
buckets. They are invisible. After the v2 refs are pruned the data is
gone.

## The change

In `history.go::discoverCheckpointHistory`, after the existing trailer
walk produces its `checkpoints` slice and `checkpointIndexes` map, add a
second pass that enumerates every checkpoint ID present on
`refs/entire/checkpoints/v2/main`:

1. Resolve `refs/entire/checkpoints/v2/main` (constant
   `paths.V2MainRefName`). If absent, skip this pass cleanly — same
   behaviour as today.
2. Walk the HEAD tree. The sharded layout is `<id[:2]>/<id[2:]>/` where
   the ID is 12 lowercase hex characters
   (`checkpoint.id.ShortIDLength = 12`, `id.Pattern = "[0-9a-f]{12}"`).
3. For every `<2>/<10>/metadata.json` path, reconstruct the
   `CheckpointID` (via `id.NewCheckpointID(<2>+<10>)` or the equivalent
   helper) and look it up in `checkpointIndexes`. If absent, append a
   new `discoveredCheckpoint{ID: id, Commits: nil}` and record the index.
4. Pass the augmented slice through the existing
   `sortDiscoveredCheckpoints` — sort is by ID string, so orphans land
   naturally.

`migration.go` does **not** need changes for correctness:
`migrateCheckpoint` already reads `discovered.ID`, reads v2 summary, and
iterates v2 sessions. `migrationCandidateFromDiscovered` reads
`discovered.Commits` only to render `commits=...` in the report;
orphans will render `commits=` (empty string after `strings.Join`). Render
`commits=(none)` or `commits=v2-orphan` instead — the existing
`writeMigrationCandidates` is the place.

## Subtleties

1. **`--since` / `--head` scoping.** Orphans have no commit, so
   reachability is undefined. Recommended: include orphans **only when
   neither flag is set**. When either flag is set, skip orphans and
   print a one-line warning (`N v2 orphans skipped; re-run without
   --since/--head to include them`). Rationale: the tool's two flags
   exist to scope migration to a commit range, and orphans don't fit
   that semantic. A user running the full rollback will run without the
   flags.
2. **Report counter.** Add a counter to `migrationReport` (e.g.
   `V2OrphanCheckpoints int`) and increment when an eligible candidate
   has `len(Commits) == 0`. Print it next to the existing counters.
   Makes the rollback audit explicit ("we migrated 28 trailer-referenced
   + 3 orphans = 31").
3. **List mode.** `--list` prints `<id> <commits...>`. For orphans,
   print `<id> (orphan)` so they're visible there too.
4. **Empty v2 ref.** If `refs/entire/checkpoints/v2/main` doesn't exist
   in this repo, the new pass is a no-op. Don't error.
5. **Lazy fetch.** Trees on `refs/entire/*` are not in the default
   refspec; in some repos the ref might be present but the tree blobs
   missing. Use the same fetching tree helpers `v2_read.go` uses for
   safety, or rely on `git.Repository.Worktree`-level reads — whichever
   matches the existing tool's style. The existing
   `discoverCheckpointHistory` uses raw `repo.Log`/`repo.References`, so
   plain tree reads via `repo.Object(plumbing.TreeObject, hash)` are
   consistent with the file's style.
